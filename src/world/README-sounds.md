# Hyperfy Sound System Documentation

## Overview

The Hyperfy sound system provides spatial audio playback for both embedded mob sounds and hosted character/player sounds. It consists of two core systems:

- **ServerSound** (server-side): Broadcasts sound events to all connected clients
- **ClientAudio** (client-side): Plays spatial or non-spatial sounds with pooling

## Architecture

```
┌─────────────┐         ┌──────────────┐         ┌──────────────┐
│  Mob Script │────────▶│ ServerSound  │────────▶│ ClientAudio  │
│ app.send()  │         │  (broadcast) │         │  (playback)  │
└─────────────┘         └──────────────┘         └──────────────┘
                               │                          │
                               │                          ▼
                               │                   ┌──────────────┐
                               │                   │ Sound Pool   │
                               │                   │ (max 3/mob)  │
                               │                   └──────────────┘
                               ▼
                        ┌──────────────┐
                        │   Position   │
                        │  Lookup via  │
                        │   Entities   │
                        └──────────────┘
```

## Sound URL Types

### 1. Embedded Mob Sounds (asset:// URLs)

Sounds embedded in .hyp mob files using SHA256 content addressing:

```javascript
// In mob blueprint (generated by build script)
props: {
  soundMap: {
    'rat_death_squeal': 'asset://sounds/sha256-abc123.wav',
    'rat_attack': 'asset://sounds/sha256-def456.wav'
  }
}
```

**Resolution**:
- `asset://sounds/sha256-abc123.wav` → `https://cdn.hyperfy.io/assets/sounds/sha256-abc123.wav`
- Handled automatically by `world.resolveURL()`

### 2. Hosted Character Sounds (https:// URLs)

Sounds hosted on S3/CDN for characters and players:

```javascript
// In world.settings.sounds
world.settings.sounds = {
  'footstep_grass': 'https://s3.amazonaws.com/degenquest/sounds/footstep_grass.mp3',
  'jump': 'https://s3.amazonaws.com/degenquest/sounds/jump.mp3'
}
```

**Resolution**:
- Direct S3 URLs are used as-is
- Registered in `world.settings.sounds` object

## Using Sounds in Mob Scripts

Mob scripts use the standard `app.send()` pattern to trigger sounds:

### Play a Single Sound

```javascript
// In your mob script (e.g., rat-v31-clean-architecture.js)

// Configuration
app.configure([
  { key: 'enableSounds', type: 'boolean', default: true },
  { key: 'soundMap', type: 'object', default: {} }
])

// Play sound on death
function handleDeath() {
  if (app.props.enableSounds) {
    app.send('playSound', {
      sound: 'rat_death_squeal',  // Name from soundMap
      volume: 0.9,                 // 0.0 - 1.0
      spatial: true                // Use 3D spatial audio
    })
  }
}

// Play sound on attack
function handleAttack() {
  if (app.props.enableSounds) {
    app.send('playSound', {
      sound: 'rat_attack',
      volume: 0.7,
      spatial: true
    })
  }
}
```

### Play a Random Sound

```javascript
// Play a random sound from a list
function handleFootstep() {
  if (app.props.enableSounds) {
    app.send('playRandomSound', {
      sounds: ['footstep_1', 'footstep_2', 'footstep_3'],  // Array of sound names
      volume: 0.5,
      spatial: true
    })
  }
}
```

### Sound Event Parameters

| Parameter | Type    | Default | Description                           |
|-----------|---------|---------|---------------------------------------|
| `sound`   | string  | -       | Sound name (from soundMap or settings)|
| `sounds`  | array   | -       | Array of sound names (random only)    |
| `volume`  | number  | 1.0     | Volume (0.0 - 1.0)                   |
| `spatial` | boolean | true    | Use 3D spatial audio positioning      |

## Building Mobs with Sounds

When building a mob .hyp file, use the mob builder to embed sounds:

```javascript
// In modules/mob/build/build-rat.js

import { buildMob } from './buildMob.js'

const sounds = {
  'rat_death_squeal': './sounds/rat_death_squeal.wav',
  'rat_attack': './sounds/rat_attack.wav',
  'rat_idle_squeak': './sounds/rat_idle_squeak.wav'
}

await buildMob({
  name: 'rat-v31',
  model: './models/rat.glb',
  script: './templates/rat-v31-clean-architecture.js',
  sounds: sounds,  // These will be embedded as asset:// URLs
  output: '../../../world/mobs/rat-v31.hyp'
})
```

The build system will:
1. Hash each sound file (SHA256)
2. Upload to assets storage
3. Generate `asset://` URLs
4. Add to blueprint `props.soundMap`

## Using Character Sounds

For player/character sounds (not embedded in mobs):

### 1. Register Sounds

```javascript
// In your world initialization code
import { initCharacterSounds } from './character-sounds.js'

world.on('ready', () => {
  initCharacterSounds(world)
})
```

### 2. Trigger Character Sounds

```javascript
import { playCharacterSound } from './character-sounds.js'

// Play a character sound
playCharacterSound(world, playerId, 'jump', 0.8, true)
```

### 3. Hook into Events

```javascript
// In character-sounds.js or your world script
world.on('playerJump', player => {
  world.network.send('playSound', {
    entityId: player.data.id,
    sound: 'jump',
    volume: 0.6,
    spatial: true
  })
})
```

## Sound Resolution Priority

The client resolves sounds in this order:

1. **Check `entity.blueprint.props.soundMap`** (embedded mob sounds)
2. **Check `world.settings.sounds`** (hosted character sounds)
3. **Return null** (sound not found - warning logged)

Example:
```javascript
// ClientAudio.resolveSoundUrl()

// 1. Check mob soundMap
if (entity.blueprint?.props?.soundMap[soundName]) {
  return world.resolveURL(soundMap[soundName])  // asset:// → https://
}

// 2. Check world settings
if (world.settings?.sounds[soundName]) {
  return world.resolveURL(worldSounds[soundName])
}

// 3. Not found
console.warn(`Sound '${soundName}' not found`)
return null
```

## Audio Pool Management

Each entity has a sound pool (max 3 simultaneous sounds):

- **Purpose**: Prevent audio spam from rapid sound triggers
- **Behavior**: FIFO eviction (stop oldest sound when pool full)
- **Cleanup**: Auto-cleanup when sounds finish playing

```javascript
// In ClientAudio.js
this.soundPool = new Map()  // entityId → [audio nodes]
this.maxPoolSize = 3        // Max 3 sounds per entity
```

## Spatial Audio Parameters

Sounds use Web Audio API PannerNode for spatial positioning:

```javascript
// Default spatial audio settings
pannerNode.panningModel = 'HRTF'          // Head-related transfer function
pannerNode.distanceModel = 'inverse'      // Inverse distance falloff
pannerNode.refDistance = 1                // Reference distance (no falloff)
pannerNode.maxDistance = 40               // Maximum audible distance
pannerNode.rolloffFactor = 3              // Falloff rate
```

- Sounds positioned at entity location
- Volume decreases with distance from listener
- Uses HRTF for realistic 3D positioning

## Fail-Fast Validation

Both server and client systems use fail-fast validation:

### Server (ServerSound.init)
```javascript
if (!this.world.events) throw new Error('[sound] Events system required')
if (!this.world.network) throw new Error('[sound] Network system required')
if (!this.world.apps) throw new Error('[sound] Apps system required')
if (!this.world.entities) throw new Error('[sound] Entities system required')
```

### Client (ClientAudio.init)
```javascript
if (!this.ctx) throw new Error('[audio] AudioContext not available')
if (!this.groupGains.sfx) throw new Error('[audio] SFX group not initialized')
if (!this.listener) throw new Error('[audio] Audio listener not configured')
```

**Result**: Server refuses to start if sound system not properly configured

## Event Flow

```
1. MOB SCRIPT (Server)
   app.send('playSound', { sound: 'rat_death_squeal', volume: 0.9 })

2. APPS SYSTEM
   Packages as entityEvent: [entityId, version, 'playSound', data]

3. SERVER NETWORK
   Emits 'entityEvent' to ServerSound system

4. SERVER SOUND
   - Looks up entity position via world.entities.get(entityId)
   - Broadcasts to clients:
     network.send('playSound', {
       entityId: entityId,
       sound: 'rat_death_squeal',
       volume: 0.9,
       position: { x, y, z },
       spatial: true
     })

5. CLIENT NETWORK
   Receives 'playSound' packet

6. CLIENT AUDIO
   - Resolves sound URL (asset:// or https://)
   - Gets/creates audio pool for entity
   - Creates Audio node at position
   - Plays sound through Web Audio API
```

## Performance Characteristics

### Memory Usage
- 100 mobs × 3 audio nodes = 300 max nodes
- ~10KB per node = ~3MB total for sound system
- Sounds cached by browser after first load

### Network Bandwidth
- Sound event: ~50 bytes per event
- 100 sounds/sec × 50 bytes = 5KB/sec per client
- Negligible compared to entity updates

### Audio Loading
- Average sound: 50KB
- 18 sounds per mob type: ~900KB
- Loaded once per mob type, cached

## Troubleshooting

### Sound Not Playing

1. **Check console for warnings**:
   ```
   [audio] Entity X not found for sound playback
   [audio] Sound 'name' not found for entity X
   ```

2. **Verify sound registration**:
   - Mobs: Check `entity.blueprint.props.soundMap`
   - Characters: Check `world.settings.sounds`

3. **Check audio unlock**:
   - Browsers require user interaction before playing audio
   - Click/touch/keypress required

### Sound Too Quiet/Loud

1. **Adjust volume parameter** (0.0 - 1.0):
   ```javascript
   app.send('playSound', { sound: 'name', volume: 0.5 })
   ```

2. **Check spatial audio settings**:
   - Distance from listener affects volume
   - Adjust `maxDistance` and `rolloffFactor` if needed

3. **Check user audio preferences**:
   - Users can adjust SFX volume in settings
   - Respects `world.prefs.sfx` setting

### Too Many Sounds

- Sound pool limits to 3 per entity
- Oldest sounds stopped when limit reached
- Add throttling in mob script if needed:
  ```javascript
  let lastSoundTime = 0
  const SOUND_COOLDOWN = 500 // ms

  function playSound(name) {
    const now = Date.now()
    if (now - lastSoundTime < SOUND_COOLDOWN) return

    app.send('playSound', { sound: name })
    lastSoundTime = now
  }
  ```

## Best Practices

1. **Always check `enableSounds`**: Allow users to disable sounds
2. **Use appropriate volumes**: 0.5-0.9 for most sounds
3. **Throttle frequent sounds**: Footsteps, impacts, etc.
4. **Use random sounds**: Vary idle/footstep sounds for realism
5. **Prefer spatial audio**: Use `spatial: true` for immersion
6. **Non-spatial for UI**: Use `spatial: false` for feedback sounds
7. **Keep sounds short**: <2s for most effects
8. **Compress audio**: Use MP3/OGG for smaller file sizes
9. **Test distances**: Ensure sounds audible at gameplay ranges
10. **Respect audio groups**: Sounds play through SFX channel

## API Reference

### ServerSound

#### `broadcastSound(entityId, data, ignoreSocketId)`
Broadcast a sound event to all clients.

**Parameters**:
- `entityId` (string): Entity playing the sound
- `data` (object): `{ sound, volume, spatial }`
- `ignoreSocketId` (string): Socket to exclude from broadcast

#### `broadcastRandomSound(entityId, data, ignoreSocketId)`
Pick random sound from array and broadcast.

**Parameters**:
- `entityId` (string): Entity playing the sound
- `data` (object): `{ sounds, volume, spatial }`
- `ignoreSocketId` (string): Socket to exclude from broadcast

### ClientAudio

#### `handlePlaySound(data)`
Handle network playSound events.

**Parameters**:
- `data` (object): `{ entityId, sound, volume, spatial, position }`

#### `resolveSoundUrl(entity, soundName)`
Resolve sound URL from entity blueprint or world settings.

**Parameters**:
- `entity` (object): Entity object
- `soundName` (string): Sound name to resolve

**Returns**: `string|null` - Resolved URL or null

#### `playSpatialSound(entityId, soundUrl, volume, spatial, position)`
Play a spatial sound with pooling.

**Parameters**:
- `entityId` (string): Entity ID
- `soundUrl` (string): Resolved sound URL
- `volume` (number): Volume (0-1)
- `spatial` (boolean): Use spatial audio
- `position` (object): `{ x, y, z }`
